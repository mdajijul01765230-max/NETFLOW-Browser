## 1. Honest Project Status Overview

NETFLOW Browser V2 is a hybrid mobile and web browser application composed of:
1. A React + TypeScript UI shell (`src/App.tsx`, `src/components/*`, `src/services/*`),
2. An Express server-side low-bandwidth transformation proxy (`server.ts`) that uses a **custom regex-based HTML sanitizer and article extractor (`cleanAndSanitizeHtml`)** — **not** `@mozilla/readability` or `DOMPurify` (**VERIFIED** by inspecting `package.json` and `server.ts:805-1012`), and
3. An Android Capacitor + multi-instance `android.webkit.WebView` native engine (`android/app/src/main/java/com/netflow/browser/{MainActivity,NetflowBrowserPlugin,NetflowWebViewEngine,NetflowDownloadManager}.java`).

* **TypeScript UI Shell, Interactive Contract & Express Backend:** **`VERIFIED`** by automated Node/TypeScript verification suites (`npm run lint`, `npm run build`, and all 32 `scripts/verify-*.ts` scripts recorded in `docs/TEST_RESULTS.md`).
* **Android Native Java Engine (`MainActivity.java`, `NetflowBrowserPlugin.java`, `NetflowWebViewEngine.java`, `NetflowDownloadManager.java`):** **`INFERRED`** at Java semantics level (**`VERIFIED`** by 16/16 static text/structure checks in `scripts/verify-java-static.ts`), **`NOT VERIFIED`** by `javac`/Gradle compilation (`./gradlew assembleDebug`) or physical Android device execution because this container lacks a JDK and Android SDK.
* **Release Gate Posture:** The application has not yet completed external Android APK compilation, physical phone testing, reference browser comparison on a handset, or live HTTPS backend deployment. All 8 gates in `docs/RELEASE_GATES.md` (`GATE-01` through `GATE-08`) remain **`NOT DONE`**.

## 4. Critical Technical Truths & Scope Boundaries

1. **`protectedMedia` (DRM / Widevine EME) Defaults to `BLOCK` and Playback Is `NOT VERIFIED`:**
   - Per-domain `protectedMedia` permission defaults to **`block`** (never `ask` or `allow`). Even when a user explicitly changes a trusted HTTPS domain's `protectedMedia` setting to **`allow`** in `SiteSettingsModal` and `NetflowWebViewEngine.resolvePermission` grants `PermissionRequest.RESOURCE_PROTECTED_MEDIA_ID`, actual DRM media playback depends on the physical device's Widevine CDM provisioning and Android System WebView implementation, and is strictly **`NOT VERIFIED`** (`VERIFIED` policy in `scripts/verify-chrome-like-ux.ts`; playback `NOT VERIFIED`).
2. **DNS-SSRF Test Scope & TOCTOU Limitation:**
   - **Backend (`server.ts`):** `scripts/verify-backend-hardening.ts` (`Summary: 15/15 passed.`) verifies live HTTP requests against `server.ts`, confirming literal private/loopback/link-local/metadata IPv4/IPv6 blocking (`isUnsafeIpOrHost`) and pre-connect + per-redirect-hop `dns.lookup(..., { all: true })` validation (`resolveAndValidateDnsSafety`). However, standard `fetch()` performs its own socket-level DNS resolution after `resolveAndValidateDnsSafety` returns, leaving a theoretical DNS-rebinding Time-of-Check to Time-of-Use (TOCTOU) window on sub-second TTL records (**`INFERRED`**).
   - **Native Android (`NetflowWebViewEngine.java`):** `shouldInterceptRequest` checks literal IPs (`evaluateUrlSafety`) and resolves uncached subresource hostnames via `InetAddress.getAllByName` with a 60-second `dnsSafetyCache`, returning an empty `403 Forbidden` `WebResourceResponse` when a private/reserved IP is returned. This Java code is **`VERIFIED`** only by static text inspection (`scripts/verify-java-static.ts`), is **`NOT VERIFIED`** on a running Android device, and also has a TOCTOU gap because Chromium performs its own network fetch after `shouldInterceptRequest` returns `null` (**`INFERRED`**).
3. **Custom HTML Sanitizer in `server.ts` (Not Readability/DOMPurify):**
   - `server.ts` does **not** use `@mozilla/readability` or `DOMPurify`. Instead, `/api/browse` and reader/text-only transformations use `cleanAndSanitizeHtml` (`server.ts:805-1012`), a custom regex-based sanitizer that strips `<script>`, `<iframe>`, `<object>`, `<embed>`, `<meta http-equiv="refresh">`, inline event handlers (`on*=`), and `javascript:`/`vbscript:`/`data:text/html` URLs (**`VERIFIED`** by source inspection and `scripts/verify-backend-hardening.ts`).
4. **What `scripts/verify-native18.ts`..`38.ts` Actually Test:**
   - Those 21 scripts test standalone TypeScript policy modules (`src/services/androidWebView*.ts`) using in-memory mocks. In the Android APK, Chromium System WebView handles WebRTC ICE negotiation, WebSocket framing, and DOM storage directly; those TypeScript classes are **not** wired into Chromium's native C++ network/media stack (**`VERIFIED`** by source inspection).
